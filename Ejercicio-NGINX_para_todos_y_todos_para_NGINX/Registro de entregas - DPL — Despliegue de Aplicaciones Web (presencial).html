Registro de entregas¶

¿Qué vas a aprender?¶

Esta página es el registro único de entregas del módulo: cada práctica guiada se entrega al campus virtual y aquí se documenta qué se entrega, con qué formato y con qué resultados de aprendizaje (RA) y criterios de evaluación (CE) se relaciona. Cada práctica enlaza aquí para conocer sus reglas comunes.

1. El modelo de entrega: microproyectos independientes¶

Todas las entregas del curso son microproyectos independientes y aislados:

  • Cada entrega vive en su propia carpeta con su propio repositorio Git (git init en esa carpeta).
  • Ninguna entrega exige haber realizado entregas anteriores: el material del profesor se copia, no se construye, y cada microproyecto se puede realizar de forma independiente.
  • Lo que se aprende en una unidad se reutiliza por conocimiento, no por dependencia de ficheros.

2. Formato común de toda entrega¶

  1. README.md con el paso a paso — documenta QUÉ se hizo, CÓMO y el RESULTADO de cada paso, con los comandos exactos usados (instalación dentro del contenedor, configuración, comprobación) y los problemas encontrados y su solución. No es un copia-pega de los apuntes: es una historia ordenada del trabajo realizado.
  2. Un commit por cambio realizado — cada paso termina con un commit descriptivo de dos partes:
  3. subject corto en imperativo (p. ej. Instalar nginx y verificar el servicio);
  4. cuerpo largo (qué, cómo y por qué), con git commit -m "subject" -m "cuerpo".
  5. Autoría de los commits — git config user.name debe coincidir con el nombre y apellidos del alumnado en el aula virtual y git config user.email con el correo del aula virtual. Se comprueba con git log --format='%an <%ae>' | sort -u.
  6. Enlace al repositorio remoto — el README incluye la URL del repositorio donde está publicado el microproyecto (GitHub, GitLab o Gitea).
  7. Evidencias en Markdown — salidas reales de comandos en bloques de código y diagramas Mermaid. No se exigen capturas de pantalla. Cuando la práctica lo pida, se añade un script de comprobación.
  8. ZIP con la carpeta .git incluida — la entrega se comprime incluyendo el historial completo del microproyecto. Si no se adjunta .git, la práctica no se valora.
  9. Entrega en el campus virtual.
  10. RA/CE asociados — cada entregable declara sus resultados de aprendizaje y criterios de evaluación del módulo (currículo oficial en El módulo DPL).

El entorno de trabajo (contenedor de laboratorio dpl-lab, cliente dpl-cliente, carpeta ~/dpl/) está descrito en Entorno de trabajo.

3. Entregas por unidad y trimestre¶

Todas las prácticas obligatorias pesan lo mismo (su media es el 50 % de la nota; ver Evaluación). Las prácticas de ampliación/cloud son formativas y no entran en la media.

Prácticas de ampliación (formativas, no evaluables)¶

Las prácticas de ampliación (Git avanzado, CI/CD con GitHub Actions, cloud con AWS/Terraform, HTTP/2-3, Node/Express, Flask, WildFly, Compose PHP+MySQL, WordPress, LDAP+nginx) se marcan como formativas: sirven para profundizar y no entran en la media. Se entregan con el mismo formato si el docente lo indica.

4. Errores frecuentes que restan puntos¶

Error Cómo evitarlo
Entrega sin la carpeta .git Comprimir siempre el microproyecto completo (.git incluido); sin él no se valora
Mensajes de commit pobres (upd, final) o varios cambios en un commit Un commit por cambio con git commit -m "subject" -m "cuerpo"
Autoría de los commits incorrecta Configurar user.name con el nombre y apellidos del aula virtual y user.email con su correo; comprobar con git log --format='%an <%ae>' \| sort -u
README sin comandos, sin paso a paso o sin enlace al repositorio remoto Documentar qué se hizo, cómo (comandos) y el resultado de cada paso, e incluir la URL del remoto
Nombre o estructura de carpeta distinta Copiar el árbol indicado en la práctica, carácter a carácter
Capturas en vez de salidas reales Pegar las salidas de los comandos en bloques de código Markdown; no se exigen capturas
Credenciales reales subidas Revisar grep -RniE "password\|passwd\|secret\|PRIVATE KEY" antes de entregar
Adjuntar la configuración sin probarla Ejecutar los comandos de comprobación y pegar su salida
Entregar fuera de plazo Respetar las fechas que publique el docente en el aula virtual; una práctica no entregada en fecha y forma se califica con 0

5. Resumen¶

  • Cada práctica guiada se entrega al campus virtual con su microproyecto y sus evidencias.
  • Toda entrega: microproyecto independiente con su propio git, README.md con comandos paso a paso y enlace remoto, un commit por cambio con autoría del aula, evidencias Markdown, ZIP con .git y RA/CE declarados.
  • Las prácticas suman el 50 % de la nota; los exámenes trimestrales, el otro 50 % (ver Evaluación).

Relación curricular¶

RA: todos (RA1 a RA6), según las tablas del apartado 3; los CE de cada práctica se listan en su propia relación curricular. Texto oficial en El módulo DPL: RA, CE y contenidos.
